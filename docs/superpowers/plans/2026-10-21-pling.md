# Pling Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Native macOS 26 menu bar + window client for ntfy with multi-server, publish, actions, attachments, reminders, and Pling E2E encryption.

**Architecture:** `PlingCore` Swift package (models, streaming client, crypto, CLI) is UI-free and unit-tested with `swift test`. The `Pling` app (XcodeGen project) owns SwiftData persistence, connection management, notifications, reminders, and SwiftUI views.

**Tech Stack:** Swift 6.x, SwiftUI, SwiftData, CryptoKit, CommonCrypto, UserNotifications, EventKit, ServiceManagement, XcodeGen.

**Spec:** `docs/superpowers/specs/2026-10-21-pling-design.md`

## Global Constraints

- Deployment target macOS 26.0. Swift 6 language mode, strict concurrency.
- No third-party runtime dependencies (XcodeGen is a build-time tool only).
- Sign only with "Developer ID Application: Justus-Constantin Weidhaus (5SB3S8ESR3)".
- No server URLs, usernames, or secrets in git. Integration env goes in `.env.local` (gitignored).
- E2E format: prefix `pling:e2e:v1:`, PBKDF2-HMAC-SHA256, salt `"pling-e2e-v1:" + topic`, 600 000 iterations, AES-GCM-256, base64url(nonce‖ciphertext‖tag).
- Re-alert: priority ≥ 4, default every 5 min, max 12 times, same notification identifier (replaces, never stacks).
- Liquid Glass only on the floating layer (menu bar panel chrome, toolbars, sidebar). Content stays plain.

### Task 2: E2E crypto

**Files:** `Sources/PlingCore/E2E.swift`, `Tests/PlingCoreTests/E2ETests.swift`.

```swift
public struct E2EPayload: Codable, Sendable, Equatable { title, message, tags, priority, click, actions, attachment: E2EAttachmentInfo? }
public struct E2EAttachmentInfo: Codable, Sendable, Equatable { name, type }
public enum E2E {
  public static let prefix = "pling:e2e:v1:"
  public static let encryptedTitle = "🔒 Encrypted message"
  public static let maxBodyBytes = 3072
  public static func key(passphrase: String, topic: String) -> SymmetricKey   // PBKDF2 600k
  public static func seal(_ p: E2EPayload, key: SymmetricKey) throws -> String  // prefixed body
  public static func open(_ body: String, key: SymmetricKey) throws -> E2EPayload
  public static func sealData(_ d: Data, key: SymmetricKey) throws -> Data
  public static func openData(_ d: Data, key: SymmetricKey) throws -> Data
  public static func isEncrypted(_ body: String?) -> Bool
  public enum Failure: Error { notEncrypted, badEncoding, tooLarge, authentication }
}
```

### Task 3: NtfyClient

**Files:** `Sources/PlingCore/NtfyClient.swift`, `Tests/PlingCoreTests/NtfyClientTests.swift`.

**Produces:**
```swift
public enum NtfyAuth: Sendable, Equatable { case none, basic(user: String, password: String), token(String)
  var header: String? }
public struct PublishRequest: Sendable { topic, title, message, priority, tags, click, delay, markdown, actions: [Action], attachment: (data: Data, filename: String)? }
public struct NtfyClient: Sendable {
  public init(baseURL: URL, auth: NtfyAuth, session: URLSession = .shared)
  public func streamURL(topics: [String], since: String?) -> URL      // /t1,t2/json?since=...
  public func messages(topics: [String], since: String?) -> AsyncThrowingStream<NtfyMessage, Error>
  public func publish(_ r: PublishRequest) async throws -> NtfyMessage   // JSON publish to base URL, or PUT with headers when attachment
  public func fetch(_ url: URL) async throws -> Data                    // attachments with auth
  public enum Failure: Error { unauthorized, http(Int) }
}
```
Notes: publishing with attachment uses `PUT /<topic>` with body = file and headers `Title`, `Message`, `Priority`, `Tags`, `Click`, `Filename`, `Delay`, `Markdown`, `Actions` (JSON). Without attachment use JSON publish `POST /` `{topic,title,message,priority,tags,click,delay,markdown,actions}`. `messages` emits only `.message` events (others consumed internally); 401/403 → `.unauthorized`.

- [ ] Tests with a `URLProtocol` stub: stream URL composition and `since` encoding; line stream with partial chunks and keepalives emits two messages; 401 → `.unauthorized`; JSON publish body shape; PUT publish headers.
- [ ] Implement using `session.bytes(for:)` + `.lines`.
- [ ] PASS. Commit `feat(core): ntfy client`.

### Task 6: Persistence, Keychain, ConnectionManager

**Files:** `App/Model/Server.swift`, `Subscription.swift`, `StoredMessage.swift`, `App/Services/Keychain.swift`, `App/Services/ConnectionManager.swift`.

```swift
@Model final class Server { var id: UUID; var name: String; var url: URL; var authKind: AuthKind(.none/.basic/.token); var username: String?; @Relationship(deleteRule: .cascade) var subscriptions: [Subscription] }
@Model final class Subscription { var id: UUID; var topic: String; var displayName: String?; var emoji: String?; var mutedUntil: Date?; var minPriority: Int; var hasPassphrase: Bool; var server: Server?; var lastMessageID: String? }
@Model final class StoredMessage { @Attribute(.unique) var key: String /* serverID|id */; var ntfyID; var time; var topic; var title; var body; var priority; var tags: [String]; var click: URL?; var actionsJSON: Data; var attachmentJSON: Data?; var isMarkdown; var isRead; var acknowledgedAt: Date?; var isEncrypted; var decryptFailed; var rawBody: String?; var subscription: Subscription? }
enum Keychain { static func set(_ secret: String, account: String); static func get(account:) -> String?; static func delete(account:) }   // service "Pling", account "<serverID>.password|token|e2e.<subID>"
```

Ingest: dedupe by key; decrypt if encrypted and passphrase present; insert; update `lastMessageID`; if `shouldNotify` → `Notifier.post`; prune > retention days on start and daily. Reconnect backoff 1,2,4…60 s; observe `NSWorkspace.didWakeNotification` and `NWPathMonitor` to reconnect immediately.

### Task 7: Notifications, actions, reminders

**Files:** `App/Services/Notifier.swift`, `ActionRunner.swift`, `ReminderScheduler.swift`.

- Categories built per message: up to 3 ntfy actions + `ACK` ("Acknowledge", priority ≥4), `SNOOZE_15`, `SNOOZE_60`, `SNOOZE_TOMORROW`, `REMINDERS` ("Add to Reminders"). (macOS shows these in the Options menu.)
- `post(message)`: identifier = message key; interruption `.timeSensitive` for ≥4; sound `PlingUrgent.aiff` for 5, none for 1, default otherwise; `threadIdentifier` = topic.
- Delegate: default tap → open window at message (or click URL); actions dispatch to ActionRunner / ReminderScheduler.
- ReminderScheduler: `scheduleRealert(key)` schedules one pending request `realert.<key>.<n>` at +interval; on fire (delegate `willPresent`) increments n ≤ 12 and reschedules unless acknowledged; `acknowledge(key)` removes pending + delivered. Snooze = calendar trigger with same content, id `snooze.<key>`. `addToReminders(message)` via `EKEventStore.requestFullAccessToReminders()`.
- [ ] Manual: `curl -H "Priority: 5" -H "Actions: view, Open, https://example.com" …` → time-sensitive banner, action works, re-alert after interval (set 1 min in DEBUG), ACK stops it, snooze re-delivers, Reminders entry created. Commit.
